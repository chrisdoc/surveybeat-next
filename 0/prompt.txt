## Key requirements (also in #37)
- AuthKit hosted UI: the six-digit email code, Google, Microsoft. The Main Worker handles `/auth/login`, `/auth/callback`, and `/auth/logout`, with a sealed session cookie (HttpOnly, Secure, SameSite=Lax), refresh, and logout. Use `@workos-inc/node` (exact pin; respect pnpm minimumReleaseAge and never add minimumReleaseAgeExclude), constructed per isolate from `env`.
- **Per-request session check:** local JWT verification plus our own deny check (revoked session, Person removed, Membership ended). Access tokens last about 5 minutes. SPEC §6.2: don't use KV for sessions that must be revoked at once. Decide where the deny list lives (D1 or the Organization DO) and record why.
- **First sign-in with no matching Person:**
  - an email on the allowlist (`ORG_CREATION_ALLOWLIST` secret, comma-separated, read per stage) sees "Create an Organization" (name only). This is idempotent per WorkOS user (double submits and retries create exactly one), and the creator becomes the Organization admin, with WorkOS org role `admin`;
  - anyone else sees "You're not part of an Organization yet".
- **Linking:** a WorkOS user links to a Person only by an exact match on a VERIFIED email. An unverified email never links. A verified email that matches Persons in several Organizations gets an Organization picker.
- **D1 global index** (`packages/cloudflare/d1-migrations/`): WorkOS user → Persons, and email → Organizations for Persons not yet linked. Design the schema. Tokens and emails are case-normalised. No survey content.
- Secrets reach Workers through Alchemy (`Config.Redacted`), and in CI through the GitHub secrets `WORKOS_API_KEY`, `WORKOS_CLIENT_ID`, `ORG_CREATION_ALLOWLIST`. Wire them into `.github/workflows/preview.yml`. Also generate a cookie-sealing password per stage (Alchemy `Random`, or a secret).
- **Verify the WorkOS key on the first preview deploy:** the redirect URIs are configured ONLY on the SurveyBeat Staging environment, so if the key belongs to another environment, sign-in fails. Add a smoke check that the authorization URL for the stage is accepted, or explain how you verified it.
- Configure WorkOS logout URIs for the same hosts with `workos authkit logout-uris set --environment-id REDACTED ...` (the CLI is logged in on this host). Also report whether Email code, Google, and Microsoft are enabled. If the CLI can't show this, say so and don't guess.
- The web app gets minimal screens: Sign in, Create an Organization, Not part of an Organization, and the Organization picker. Use the message catalog, Tailwind, and Base UI. TanStack Router may be added now if needed (exact pin).
