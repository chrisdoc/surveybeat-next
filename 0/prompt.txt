**1. A failed enqueue strands a resent send in Pending, and the retry can't recover it**
- The code is `Organization.ts` `resendFailedEmail` (the `state._tag !== "Failed"` branch, about line 1583), together with `DirectoryFlow.ts` `resendFailedEmail` (`if (result.queue) yield* … queue(...)`).
- The DO commits Failed → Pending first, and the Worker enqueues afterwards. If the queue send dies between the two (isolate eviction or a queue outage), the send stays Pending with nothing queued.

- This matches how other sends already work (create, then queue), and the `EmailOutbox` doc says "Delivery is idempotent per send, so repeats are safe". So I rate it minor.
- Fix: also return `queue:true` when the state is `Pending` with `attempts == 0`, since a duplicate queue message is harmless. Alternatively, accept the gap and note it.
