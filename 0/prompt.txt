## Blocking

1. **The notice says the Edit key never leaves the browser except as a hash. It does.**
   - `apps/web/src/messages/legalPrivacy.ts`, `legal.privacy.s09.tedit.what`: "It never leaves the browser except as a hash."
   - In the code, `apps/web/src/answer/main.ts:641-645` sends the raw `editKey` to `POST /answer` on every later save. `SubmissionRoutes.ts:280-284` hashes it on the server.
   - ADR 0005 says so too: "sends only its SHA-256 hash with the first Answer. Later Answers and changes carry only the Edit key."
   - Suggested wording: only a hash goes with the first answer; to change answers the browser sends the key itself over HTTPS; the server stores only the hash.

2. **The retention text describes a setting and a deletion that don't exist.**
   - `legalPrivacy.ts`, `s03.tanswers.retention`: "24 months unless the Organization sets another period."
   - `legalAgreements.ts`, `legal.dpa.s08.p1`: Submissions "are deleted when the Organization's retention period for them ends."
   - Nothing in the migrations or code stores a retention period or deletes anything on one. SPEC §5.3 calls for the setting, but it isn't built.
